# litellm was upgraded off the last known-safe pre-compromise pin (1.82.6) once
# a verified-safe post-quarantine release was available. Versions 1.82.7 and
# 1.82.8 were compromised with credential-stealing malware (March 2026 PyPI
# supply-chain incident, TeamPCP / Trivy CI token compromise). litellm's own
# security update (docs.litellm.ai/blog/security-update-march-2026) confirms
# all releases from v1.78.0 through v1.82.6 as clean, and recommends v1.83.0+
# (built on a new, isolated CI/CD v2 pipeline with signed releases) going
# forward. Pinned here to the latest available release as of this upgrade.
#
# DECISION plan-2026-09-24T091842-c1d5bfbc/D-002: one pin, no marker split.
# Python 3.10: litellm 1.100.1 and 1.100.2 import typing.NotRequired (3.11+
# only) at import time, so `import litellm` fails on 3.10; that kept the CI
# 3.10 leg red from v0.8.0 on. 1.101.0 is the first fixed release (it imports
# NotRequired from typing_extensions); 1.101.0-1.102.1 were checked to import
# on 3.10. Versions 1.83.0-1.100.0 were NOT checked on 3.10. One pin for every
# Python version on purpose: a per-version marker split would recreate the
# CI-vs-local drift described below. Do not go back to 1.100.x.
litellm==1.102.1

# Dev toolchain — exact pins so CI and every developer resolve the SAME tools.
#
# WHY: these were unpinned, so CI and local boxes silently resolved different
# versions, and that drift alone caused two separate CI outages:
#   * mypy      — CI resolved 2.3.0 while local had 1.19.1, producing a
#                 type error no local run could reproduce.
#   * pytest    — CI resolved 9.1.1 while local had 8.3.5, producing a
#                 collection failure no local run could reproduce.
# See plans/LESSONS.md [I:5]. Pinning freezes a state measured green under
# every one of these versions; it is a freeze, not a migration.
#

# tools receive no upstream fixes until a human does this):
#   1. Raise the version(s) below.
#   2. .venv/bin/python -m pip install -c constraints.txt -e ".[dev,workflows,reasoning,agents,monitor]"
#   3. Run the full local gate: pytest, mypy src/, ruff check, ruff format --check.
#   4. Push and confirm a green GitHub Actions run on all three matrix legs.
# One PR that raises all six at once, with CI as the acceptance test, is the
# intended cadence.
# ---------------------------------------------------------------------------
