# fsm_llm

Path: `src/fsm_llm`
Purpose: The FSM-LLM package: core engine (JSON-defined finite state machines driven by an LLM through a 2-pass pipeline) at the top level, plus the subpackages (reasoning, workflows, agents, monitor, eval, synthesis, testing) built on it.

## Scope

- Layout: this directory IS the import package `fsm_llm` (src layout: `src/fsm_llm/`). `pyproject.toml` finds it, its extras-backed subpackages and its layer packages (`security/` from step 67, `core/` from step 69, `llm/` and `context/` from step 72, `handlers/` from step 77, `engine/` from step 78, `okf/` from step 83, `skills/` from step 84, `tools/` from step 85 and `policy/` from step 86 of plan d454fd62, `runtime/` from plan 21e6f00d; they ship with the core and need no extra) with `[tool.setuptools.packages.find]` (`where = ["src"]`, `include = ["fsm_llm*"]`, `namespaces = false`), so a new subpackage needs no list entry. The editable install writes a plain `.pth` holding `<repo>/src`, which is harmless: `src/` holds only this directory. Never put `src/fsm_llm/` itself on `sys.path` (running a file from inside it as a script does): it holds `logging.py` and would shadow the stdlib. `src/fsm_llm.egg-info/` (generated by `pip install -e .`, gitignored, removed by `make clean`) sits beside this directory. mypy follows the layout through `mypy_path = "src"`. A clone from before the package moved here (plan d454fd62, step 62) must run `pip install -e .` again. The old `src/fsm_llm_agents`, `src/fsm_llm_reasoning`, `src/fsm_llm_workflows` and `src/fsm_llm_monitor` dirs do not exist; do not recreate them.
- Top-level modules: the core. `API`, `FSMManager`, `MessagePipeline`, Pydantic models, JsonLogic, handlers, classification, the LLM layer (the only litellm import), prompts (`context/layout/`), context security, working memory, sessions, the validator (`core/verify/`), the visualizer (`core/visualize/`), CLI, Open Knowledge Format (`okf/`, `engine/okf_bridge.py`, the kernel `text.py`), Agent Skills (`skills/`), the tool layer (`tools/`), the approval and HITL layer (`policy/`), the opt-in event log (`runtime/`), their shared YAML frontmatter seam (`frontmatter.py`) and their shared CLI skeleton (`cli_support.py`), and the graph analyses of runtime synthesis (`core/verify/flow.py`).
- Subpackages: `reasoning/`, `workflows/`, `agents/`, `monitor/`, `eval/`, `synthesis/`, `testing/`. Role, entry points and the core contracts each relies on are in the Subpackages table below; this file is the contract reference for the core and the cross-package rules.
- Version 0.13.0 in `__version__.py`; every subpackage re-exports it. Python 3.11-3.15. Core deps (pyproject): loguru, litellm (>=1.109.0,<2.0), pydantic (>=2.0,<3), python-dotenv, pyyaml (>=6.0,<7; parses OKF and Agent Skills YAML frontmatter in `frontmatter.py`, declared explicitly because it was only a transitive dependency), tenacity (needed by litellm's sync retry path; nothing here imports it, do not remove).
- `__init__.py` never imports a subpackage, and loads only the layers the public API needs (`core`, `engine`, `handlers`, `context`, `llm`, `security` and the kernel modules `aio`, `constants`, `env`, `logging`, `memory`; pinned by `tests/test_fsm_llm_regression/test_import_laziness.py`) (DECISION D-003 of plan 3a032517: they import `from fsm_llm import API`, so an eager import hits a half-initialised package, and monitor would drag fastapi into core installs). Do not add eager imports or a module `__getattr__`. `has_workflows/get_workflows`, `has_reasoning/get_reasoning`, `has_agents/get_agents` probe by dotted name; `get_*` gives the install hint only when the package itself is missing.

## Architecture

```mermaid
flowchart TD
    API[engine.api.API] -->|fsm_loader closure| FM[engine.fsm.FSMManager]
    FM -->|per-conv TurnGate + _active_turns| MP[engine.turn.MessagePipeline]
    MP --> PRE[PRE_PROCESSING handlers]
    PRE --> DX[executor_for(state).extract: completion call, or bulk + field + retries]
    DX --> CU[context.update + CONTEXT_UPDATE handlers + provenance]
    CU --> CX[classification_extractions]
    CX --> TE[TransitionEvaluator: DETERMINISTIC / AMBIGUOUS / BLOCKED]
    TE -->|AMBIGUOUS| AC[_resolve_ambiguous_transition via Classifier]
    TE --> ST[_execute_state_transition: PRE/POST_TRANSITION, rollback]
    ST --> PX[post-transition extraction / back-edge re-run]
    PX --> POST[POST_PROCESSING handlers]
    POST --> RG[Pass 2 response generation; a silent state, empty response_instructions, makes no call and no reply]
```

Lock order is `FSMManager._lock -> conv_lock` everywhere (`conv_lock` is a `TurnGate`, `engine/fsm/gate.py`, owned by a ticket in a ContextVar and not by a thread, so it works under asyncio; plan f150ec28 D-004); never take `_lock` while holding a `conv_lock`. `FSMManager._fsm_cache_lock` is a leaf lock (never take another lock or run the loader under it). `API._stack_lock` is a plain non-reentrant `Lock`, never held across `FSMManager` calls.

Subpackage dependencies (solid = required, dotted = optional):

```mermaid
flowchart LR
    reasoning --> engine
    workflows --> engine

    agents --> tools

    agents -. permanent debt, D-016 c .-> reasoning
    monitor --> engine
    monitor -.-> agents
    monitor -.-> workflows

    synthesis --> engine

```

Each arrow is an allowed import (a subpackage names the layer package it reads; the full order is the `layers-section-5-2` contract of `.importlinter` and the root `AGENTS.md`). Solid arrows between a subpackage and a layer are required, dotted arrows are optional or named debts.

- `evaluate_logic(logic, data)`. Operators (`constants.ALLOWED_JSONLOGIC_OPERATIONS`): `== === != !== > >= < <=`, `! !! and or if`, `in contains`, `+ - * / % min max`, `cat`, `var missing missing_some`, custom `has_context`, `context_length`. None rule: ordering operators are False with a None operand; arithmetic on None, or that cannot compute (non-numeric operand, wrong arity; zero divisor still raises), yields a private UNDEFINED that makes every comparison and membership False and `evaluate_logic` return None; `null == null` is True; `==` is loose: with a bool operand a string compares as lowercased text (`true == "true"`, `"True"`; not `"1"`) and a number by truthiness (`true == 1`, `true == 2`, `false == 0`), two strings compare case-insensitively and never numerically (`"01" == "1"` is False), and a number vs a plain ASCII numeric string numerically (`1.0 == "1"`); use `===` for a strict gate (the meta-builder does); "missing" means absent, None or `""` (`expressions.is_missing`); `%` keeps Python floored semantics. `<`, `<=`, `>` and `>=` coerce a string operand to a number only when it is a plain decimal or scientific literal (padding trimmed; `"inf"`, `"Infinity"`, `"1_000"` and non-ASCII digits stay text, as for `==`, D-048), and an integer past float range orders exactly, never as an `OverflowError`; a two-argument `has_context` with a non-string key logs a WARNING and is False, and `missing_some` with names that are not a list raises `TransitionEvaluationError` (plan 52ce5464 C1, C2).
- CLI (pyproject scripts): `fsm-llm --fsm F [--mode run|validate|visualize] [--style full|compact|minimal] [-n history] [-l msglen] [--model/-m M] [--env-file PATH]`, `fsm-llm-validate --fsm F [--upgrade]`, `fsm-llm-visualize --fsm F [--style] [--format ascii|mermaid|dot]` (`--style` is ASCII only; `fsm-llm --mode visualize` has no `--format`). `run` needs env `LLM_MODEL` (optional `LLM_TEMPERATURE`, `LLM_MAX_TOKENS`) and reads a `.env` only with `--env-file PATH` (`env.load_env`; nothing loads one unasked, `llm/providers/litellm.py` sets `LITELLM_MODE=PRODUCTION` around `import litellm`; `--model` beats the process environment, which beats the file); with no model `fsm-llm` prints `Error: <ModelNotConfiguredError message>` to stderr and exits 1; a failure of the first model call (`start_conversation`) prints `Error: ...` to stderr and exits 1, like a later turn; `--fsm` is mandatory (`__main__` checks it first, so env `FSM_PATH` is read only by a Python call `runner.main(fsm_path=None)`, never by the `fsm-llm` script). Core scripts `fsm-llm-okf <validate|list|show|search|export>` (`okf/cli.py`) and `fsm-llm-skills <validate|list|show> PATH...` (`skills/cli.py`). Subpackage scripts: `fsm-llm-monitor`, `fsm-llm-meta`, `fsm-llm-eval` (with no model named it exits 1 with the `ModelNotConfiguredError` line; a monitor launch route answers 400; there is no default model, plan ace7a8c8 D-048); each, and `python -m fsm_llm.reasoning`, takes the same `--env-file PATH` (`cli_support.add_env_file`).

## Data shapes

- `FSMDefinition{name, description, states: dict[str, State], initial_state, version="4.3" (`core.definitions.schema.SCHEMA_VERSION_DEFAULT`), persona, handler_only_keys=[]}`. Load checks: initial state exists, `state.id == key`, transition targets exist, a reachable terminal state, no orphaned states.
- `State{id, description (<=300), purpose (<=500), extraction_instructions, response_instructions, transitions, required_context_keys, extraction_retries (=1), extraction_confidence_threshold, transition_classification, field_extractions, classification_extractions, context_scope: ContextScope{read_keys, write_keys}, completion: CompletionStateConfig | None, synthesize: SynthesizeConfig | None}`. A state without transitions is terminal. The names of `field_extractions`, `classification_extractions` and `required_context_keys` must be non-blank and not internal-prefixed (refused at load and by `fsm-llm-validate`, plan 52ce5464 B5).
- `CompletionStateConfig{tools (OpenAI function schemas, unique names) | response_format_key (internal key holding a response format), exactly one; tool_choice (auto, required, none or a declared tool name; tools only), instructions (system message, no cap), messages_key="_completion_messages" (internal), result_key="completion_result" (public, not reserved)}` (frozen, `extra="forbid"`). A completion state declares no `field_extractions`, `classification_extractions`, `required_context_keys` or `extraction_instructions` and is not terminal; `fsm-llm-validate` warns when its transitions do not cover every result kind.
- `SynthesizeConfig{goal (1 to `SYNTHESIZE_GOAL_MAX_LENGTH` chars, not blank), inputs, return_keys (at least one; public names only), on_failure (a state id one transition of the state reaches), result_key="synthesis_result" (public; never an input or return key), min_lifecycle="verified"|"trusted"}` (frozen, `extra="forbid"`; `DEFAULT_SYNTHESIS_RESULT_KEY` lives in `core/definitions/limits.py`, not `constants.py`). A synthesize state declares no `completion`, `field_extractions`, `classification_extractions`, `required_context_keys` or `extraction_instructions`. Loader checks (`_check_synthesize_states`, the real `TransitionEvaluator` on sample results): no edge of the state may pass with no result or with `status` `running`, and the edge to `on_failure` must pass for `status` `failed` and `aborted` (write `status in [failed, aborted]`; a bare `== "failed"` is refused). Every transition must read the result key or a handler-only key. Core never runs the procedure: the pipeline mints no extraction for a synthesize state and makes its `result_key` handler-only (`handler_only_names`, shared with `core.verify.flow`) and closed to every extraction channel, classification included (`result_key_names`; an author-listed `handler_only_keys` entry stays classifiable, plan 52ce5464 D-002); a bare `API` with no executor refuses it with `MissingExecutorError`. The executor is `fsm_llm.synthesis.SynthesizeExecutor` (registered with `API(executors=...)`; see `synthesis/AGENTS.md`). `fsm-llm-validate` runs no synthesize check beyond the loader (it is never stricter than the loader); its reports are the version warning, for a definition that declares `"4.0"` or `"4.1"` and uses `synthesize`, and the warning for an extraction channel of another state that names the result key (written by the executor, never extracted).
- `CompletionRequest{messages, tools, tool_choice, response_format, temperature, max_tokens, call_type="completion"}` (frozen, `extra="forbid"`, `tools` XOR `response_format`); `CompletionResponse{kind: calls|final|malformed, text, calls: tuple[ModelToolCall{id (non-empty), name, arguments: dict}], finish_reason: str | None = None}` plus the property `truncated` (`finish_reason == "length"`, the reply was cut off at `max_tokens` and `text` or the call arguments may be a fragment); `LLMUsage(LLMCallCounts{calls, errors, usage_missing, prompt_tokens, completion_tokens, total_tokens}){by_kind}`.
- `Transition{target_state, description, conditions, priority 0-1000 (=100), llm_description}`; `TransitionCondition{description, requires_context_keys, logic, evaluation_priority}`; `logic` is validated at load (allow-listed operators, one key per operator object, depth <= `MAX_JSONLOGIC_DEPTH` 50).
- `ClassificationExtractionConfig{field_name, intents (>=2), fallback_intent (one of intents), confidence_threshold, required, model, prompt_config, context_keys}`: intents sit directly on the entry, no nested schema.
- `FieldExtractionConfig{field_name, field_type, extraction_instructions, validation_rules, required, confidence_threshold}`; `validation_rules` with `min_length` above `max_length`, `min_value` above `max_value` or a negative `max_length` are refused at load (equal bounds and a negative `min_length` stay valid, plan 52ce5464 B6).
- `FSMContext{data, conversation: Conversation, metadata, working_memory (exclude=True)}`; `FSMInstance{fsm_id, current_state, context, persona, last_extraction_response, last_transition_decision, last_response_generation}`; `Conversation{exchanges [{"user"|"system": text}], max_history_size, max_message_length, summary}` (summary digests trimmed exchanges, capped at 2,000 chars, rendered as `<conversation_summary>`).
- LLM request models `BulkExtractionRequest`, `FieldExtractionRequest`, `ResponseGenerationRequest`: `user_message: str | None` (`None` = no user message: a step, the greeting, a context-only classifier call) and `extra="forbid"`. The replies `ResponseGenerationResponse` and `FieldExtractionResponse` carry `truncated: bool = False`: `llm/parsing.py` (`_flag_cut_off`, the one place) sets it from the provider's `finish_reason` `length`, a custom `LLMInterface` may set it, and `pipeline._was_cut_off` reads it as exactly `True` (a duck-typed reply without the attribute is not cut off).
- `AdvanceResult{state_before, state_after, transition_outcome, response: str | None, ended}` (frozen); `RunBudgetExceededError(budget "steps"|"seconds", limit, steps_done)`; `FSMGraph{name, initial_state, nodes, edges}` from `build_fsm_graph` (`ValueError` on a malformed definition).
- `SessionState{conversation_id, fsm_id, current_state, context_data, conversation_history, stack_depth, working_memory {"buffers", "hidden_buffers"} | None, conversation_summary, saved_at, metadata {"pipeline_extracted": digests}}`.
- Seeded context keys: `_conversation_id`, `_conversation_start` (naive local ISO text), `_timestamp` (epoch seconds), `_fsm_id`; on transition `_previous_state`, `_current_state`, `_transition_timestamp` (epoch seconds; none of the timestamps is persisted by `save_session`); ERROR handlers see `_error`, `_traceback`; push with history adds `_inherited_history`; pop with history adds `_sub_conversation_summary`. These form `constants.RESERVED_CONTEXT_KEYS`, which a handler delta can neither set nor delete.

## Invariants and constraints

- Builder convention (every builder in the repo; plan 89b03f61 D-001 to D-008): class `<Product>Builder`; mutators are `set_`, `add_` or `remove_` verbs that only record and return `self`; `build()` is the only validator and the terminal verb: it copies what the builder owns (dicts, lists, `FSMDefinition` via `model_copy(deep=True)`), raises `BuildError` (`FSMError` and `ValueError`, `.errors` lists the problems, the domain or constructor error is chained as `__cause__`), and objects the caller passed in (interfaces, stores, handlers, agents, registries) stay shared by reference. Carve-outs: the meta artifact builders (`FSMArtifactBuilder`, `WorkflowArtifactBuilder`, `AgentArtifactBuilder`) still refuse a bad call at call time with `BuilderError` (the LLM tool path needs it), keep `update_state`, and report warnings through `take_warnings()` (their tools serialise calls per builder; direct builder calls are not serialised against tool calls); `HandlerBuilder` keeps its `at`/`on_state`/`when`/`do` vocabulary (frozen examples use it). A new builder passes to the real constructor only what was set, never copies the constructor's validation or filters option names, and gives open-ended input its own setter (`set_llm_option`, `set_option`, `set_api_option`) whose names `build()` checks against the constructor signature (never a list) and refuses when one repeats a named parameter (`fsm_llm.engine.builders.refuse_named_options`, not exported). Config copies are shallow: callables inside stay shared. No shared base class.
- Transitions: a transition passes only if all its conditions pass. Unique lowest `priority` among passing transitions -> DETERMINISTIC, whatever the gap; a tie at the lowest priority -> AMBIGUOUS, only the tied group goes to a `Classifier`, one option per distinct target (equal-priority transitions to one target are one candidate, DETERMINISTIC when it is the only target); error, fallback intent or a tie set the schema cannot hold (15+ distinct targets, a target named `_stay_in_state`; `fsm-llm-validate` warns) = stay; none -> BLOCKED (stay). The gate reads the committed context only (the pipeline passes no extracted data): a CONTEXT_UPDATE handler's overwrite or delete of an extracted key is what the transition decides on. No confidence score; `TransitionEvaluatorConfig` has only `strict_condition_matching` and `detailed_logging`. `required_context_keys` only guides extraction; gate with a condition.
- Turn atomicity: `process()` deep-copies `current_state`, `context.data`, `working_memory`, `metadata` first. PRE_PROCESSING failure restores. POST_PROCESSING or Pass-2 failure restores the whole turn, including Pass 1's transition. Inside Pass 1: CONTEXT_UPDATE failure rolls back only the committed keys; POST_TRANSITION failure restores the pre-transition snapshot. Handler external side effects are never undone.
- `FSMManager`: a failed turn pops the just-added user message; ERROR handlers run for any exception (stream path too) except `KeyboardInterrupt`, `SystemExit`, `GeneratorExit`; an ERROR handler's raise replaces the original (chained); ERROR deltas are not merged. `end_conversation` waits `END_CONVERSATION_LOCK_TIMEOUT_SECONDS` (30) for a running turn, then raises `ConversationBusyError` without tearing anything down. `API.end_conversation` reads its cache with the same bounded wait, ends frames before dropping bookkeeping, and propagates a refusal; `cleanup_stale_conversations` and `close()` log it and continue.
- Handlers: `register_handler` is copy-on-write under a lock and rejects a non-real priority (`TypeError`) or NaN (`ValueError`). A failure is wrapped once in `HandlerExecutionError` (pickles). With `handler_timeout`, each handler runs on its own deep copy in a daemon thread; a timed-out result is discarded; while `MAX_TIMED_HANDLER_STRAGGLERS` (4) timed-out threads still run, a new timed call fails at once. Zero handlers at a timing skips the deep copy.
- Re-entrancy: a same-conversation `converse`/`converse_stream`/`advance`/`advance_stream` (and the `a` twins) while a turn is in flight raises `FSMError` and never waits; `update_context` and reads are allowed from the turn's own task, its child tasks and `to_thread` workers (they inherit the ticket), a plain thread waits for the turn in arrival order, and a reader or `end_conversation` called from a SIBLING task of the loop during an async turn raises `ConversationBusyError` at once. Streams acquire `conv_lock` lazily on first `next()` (or `__anext__`); existence is validated at call time.
- Async turn (plan f150ec28): handlers run inline on the loop; a sync-only interface runs on `to_thread`; `apush_fsm` is the one push body and `push_fsm` its `run_sync` wrapper (plan baa37f40 D-020, which supersedes the cut of plan f150ec28 D-015: a cancel inside the child's greeting leaves no child, no in-flight id and the parent as it was; a sync `push_fsm` inside a running loop blocks it for the greeting). A cancelled turn is rolled back whole by one `except asyncio.CancelledError` arm per turn body in `engine/turn/driver.py` plus the manager arms (D-002): snapshot restored, user message popped, gate released, budget counted, no ERROR or END handler. `aclose` of a stream (abandonment) keeps the partial reply; `athrow(CancelledError)` into a suspended stream is abandonment too (D-017), and so is a cancel or `break` in the consumer's own code (the conversation stays claimed until the generator is closed, use `contextlib.aclosing`). Known limits (D-019, D-020, D-021): a sync-only custom `StateExecutor` may write into the conversation after a cancel (its worker thread holds the live instance; override `aextract`); a subclass of a built-in executor that overrides only the sync `extract` or `after_transition` is bypassed in async mode (override the `a` twin too, no warning); a handler or tool that outlived its timeout keeps the turn ticket; the task that ran a stream's first step owns the conversation between chunks; a sync run loop given an async `before_step` that really suspends raises `SuspendedInSyncModeError`; `API.close()` leaves an owned event log open while a turn is in flight. With the event log on, the boundary writes of an async turn run as one job each on a lane thread (plan 3f4530d3 step 8, `runtime/lanes.py`); the loop census of `test_event_log_census.py` is zero for a scripted conversation, and the writes still inline on the loop (a streamed reply's last write, push, pop, `update_context`, a delegated run start, a tool, approval or handler body run inline, `FileSessionStore.save`) are the named limits of the root `AGENTS.md`.
- Terminal state: `converse` and `advance` raise `FSMError("Conversation has ended ...")`. A silent state (empty `response_instructions`) makes no Pass-2 call on any entry: `start_conversation` and `converse` return `""`, streams yield nothing, `advance` returns `response=None`, and nothing is added to history (no marker).
- Message-free step (`advance`): the same turn with `user_message=None`; no user exchange in history; per-field, bulk, classifier and Pass-2 prompts use their no-message wording (the bulk prompt is built from the scoped, security-filtered context and fills unset keys only); the LLM layer sends `NEUTRAL_USER_TURN` as the provider user turn. An empty `converse` message is a different fact and is sent as `EMPTY_USER_MESSAGE_TURN`. `run_until_terminal` checks per round: ended (a conversation closed mid-run ends the run normally), seconds budget, steps budget, `before_step(n)`, then one `advance`; budgets are checked only between steps. When the top of the stack is an ended pushed FSM (depth above 1) and a hook is given, `before_step(n)` is called once first (not a step, not budget-gated, `n` is the next step's number): if it pops (or the top is no longer ended) the run continues, else it returns normally; an ended frame pushed by a `call` state is popped by the loop itself through `settle` first (plan baa37f40 D-024), so a resumed or refused-end call finishes. `seconds_exempt_states`: a round whose current state id is in the set runs past a spent seconds budget (steps still count).
- Completion state: Pass 1 is one `complete` call over `[system(instructions)] + context[messages_key]` (no prompt builder text, no history, no neutral user turn), made only while `result_key` is unset; the result is committed without `clean_context_keys` and is handler-only for extraction; nothing is minted for extraction. A transcript `check_tool_transcript` refuses, a tool-calling turn whose transcript has no `user` message, or a missing structured response format raises `LLMResponseError` before sending and rolls the turn back; an outage rolls back like any Pass-1 failure. A pushed child does not inherit a completion result key. Core never runs a tool.
- Synthesize state (D-002 and D-017 of plan 2cefeb61; the engine half of D-002 is superseded by D-041 of plan baa37f40): the pipeline mints no extraction for it, and its executor, `fsm_llm.synthesis.SynthesizeExecutor`, writes `context[result_key]` (`{status, procedure_id, version, reason}`, codes and ids only) in Pass 1 and through the settle step. The kind sets `requires_executor`: a bare engine refuses the state with `MissingExecutorError` (it used to stay BLOCKED for ever). Do NOT restore the conversation fallback for it, do NOT put the executor in the module table (a subpackage, and every `API` of the process would share one synthesizer), and do NOT make `FSMValidator.validate()` stricter than the loader (never-stricter tests pin it); the `core/definitions/state.py` anchor on `State.synthesize` says why. The minting rule is one hook, `state_kinds.KindSpec.minted_keys` (the pipeline and `core.verify.flow` both read it; the D-017 anchor sits there); change it only there and with the equality corpus.
- Cut-off record (D-025): `core.definitions.CONTEXT_KEY_CUT_OFF` (`"_cut_off"`, an internal key in `context.data`, so in no prompt, not in `get_data` and not in a saved session; lives in `core/definitions/completion.py`, not `constants.py`, which a bench file pins). Value `{"reply": True}` (Pass-2 reply cut) and/or `{"fields": [names]}` (field extractions in call order, or a completion state's `result_key`); ABSENT when nothing was cut. Written only by `context.record_cut_off` (called by the pipeline and the completion executor; copy-on-write, JSON-native values); removed at the start of `_run_turn`, `_stream_turn` and the greeting (after the rollback snapshot, so a rolled-back turn restores the prior record), so it describes the LAST turn only. A streamed reply is never flagged. The completion-state result stays `{kind, text, calls}`. Do not re-derive a cut from reply text and do not add a second flag; `agents.base.BaseAgent` and `REWOO` read it (`get_data` does not show it; the raw context does, `fsm_manager.copy_raw_context_data`).
- Provenance: `context.metadata["_pipeline_extracted"]` holds a digest per pipeline-extracted key. Bulk extraction overwrites a stored key only if config-covered, the FSM is not agent-managed (`agent_trace` in context), and the stored value still matches its digest; handler and `update_context` values are never overwritten. Refused corrections reach Pass 2 as `<rejected_corrections>`. `handler_only_keys` are never written by the bulk or per-field channels; a listed key that a `classification_extractions` entry owns stays classifiable in Pass 1 and after a transition, while a completion or synthesize `result_key` is closed to every channel (`result_key_names`, plan 52ce5464 D-002, the owner's option A).
- Post-transition (non-agent FSMs): the new state's missing config-covered keys are extracted; entering a different state whose keys carry provenance re-runs its Pass-1 extraction (not for self-loops or states with `classification_extractions`).
- Classification records: full results at `context.metadata["classification_results"][field]` (secret-looking snapshot entries dropped); only the intent string enters `context.data`. Ambiguous-transition record at `context.metadata["transition_classification"]` only, cleared at turn start. Classifier: the pipeline injects its own `llm_interface` (`Classifier(llm_interface=...)`) unless the entry's `model` differs from the interface's model (then a private interface with no inherited kwargs). Cache: per pipeline, content plus interface identity, max 64 (`MAX_CLASSIFIER_CACHE_SIZE`), under `_classifier_cache_lock`; per-call prompt and context stay out of the key. Soft-fail (stay, or leave the key unset, with a WARNING) only on `ClassificationError`; a `Classifier` that cannot be built over an interface without `complete` is a `ClassificationError` too, any other construction error or exception from a custom `complete` fails the turn.
- Security: internal prefixes `_`, `system_`, `internal_`, `__` only via `has_internal_prefix` (case-insensitive); never re-inline `startswith("_")`. `FSMContext.update` writes internal-prefix keys without a WARNING (D-026: every caller that reaches it writes the key by name through a public path; extraction results are stripped by `clean_context_keys` and handler deltas bypass it); guard a new accidental-write path at that path, never by re-adding a warning there. The reserved-key WARNING of a handler delta stays. Secret-looking entries only via `is_forbidden_context_entry(key, value)`: name patterns, whole-segment credential names (`pin`, `pass`, `pwd`, `otp`, `cvv`, `cvc`, `ssn`, `jwt`, `cookie`, `bearer`, `authorization`, `card_number`, ...; digit suffix and camelCase/acronym forms match) that strip unless the value is a `bool` or the tail is only policy suffixes and the value is not credential-shaped, plus value-shape layers for `*_key`/`*_token` (a digit run after the trigger word is part of the name: `key1`, `token2`, `secret1`, `private_key2` strip like `key`; under an ambiguous `*_key` name the string leaves of a list, tuple, set or dict value and a bytes value are judged by the same value test, bounded and failing closed). The filters share `MAX_CONTEXT_FILTER_DEPTH = 16` (fail closed) and drop cycles: `fsm._strip_internal_mapping` (`get_data`, `save_session`), `context.clean_context_keys` (committed extraction), prompt filter in `context/layout/base.py`. Only the prompt filter has the truncating budget `MAX_CONTEXT_FILTER_NODES = 100_000`; `context.filtering.filter_context_tree` never truncates and raises `ContextFilterError` (an `FSMError` and a `ValueError`) on a pathological cycle.
- OKF: bundle text is untrusted. It reaches a model in three ways, all capped and control-stripped: tool output (agents), summaries in a public context key (`engine.okf_bridge.create_okf_handler`, records with `trust_claimed`), and the labelled `OKFMemoryBackend` summaries concatenated into the task string; never as a tool description, `instructions`, persona or state instruction. `executor`/`attester` resources are never executed. The trust tier (`verified[].by`) is the bundle's own claim, advisory, never authorization, and is shown as `trust (claimed by bundle)`. Bundle paths go through the shared helper `security.resolve_within` (resolve first, compare path components; symlinks are skipped; hardlinks are an accepted residual, not detected). A spent load bound is flagged by the agents tools (a fixed note with issue codes only) and the CLI, not by handler records or `OKFMemoryBackend` summaries (`.incomplete` and `bundle.issues` carry it). `parse_concept_text` never raises: a PyYAML constructor failure is a `frontmatter-invalid` issue. Do not add a second YAML loader: `okf/parser.py` and `skills/catalog.py` both use the `SafeLoader` subclass in `frontmatter.py`, which refuses YAML aliases and anchors and keeps timestamps as strings, with frontmatter size and depth limits passed by each caller.
- Agent Skills: skill text is untrusted. It reaches a model only as capped, control-stripped, labelled tool output (`SKILL_UNTRUSTED_LABEL` first line of every reply) or inside `SkillCatalog.render_catalog()` output that a caller puts in a task string; never as a tool description, parameter description, `instructions`, persona or state instruction built by the library. Nothing in a skill folder is executed, imported or shelled out (no `skill_run`; `skills/catalog.py` carries the D-025 anchor of plan 4c2042f3 naming the forbidden imports), `allowed-tools` is reported and never enforced. In-skill paths go through `security.resolve_within` plus a lexical-equality check; symlinks inside a skill are skipped, dot entries are never listed or readable; hardlinks and TOCTOU are accepted residuals. The catalog keeps no body (D-022 of plan 4c2042f3). Loading never raises on content; discovery is explicit paths at depth 1; a spent bound makes the catalog `incomplete` and the agents tools and the CLI say so with issue codes only. Read-only: no writer, exporter, memory backend or plain-FSM handler. Names are ASCII; `validate --strict` checks portability against the Anthropic API rules (extra keys warn).
- Sessions: `save_session` snapshots the ROOT frame atomically (`get_conversation_snapshot`); a snapshot restores the root frame only (a pushed stack is restorable only from the event log: `API.fork(conversation_id, *, at_turn)` and `API.resume(conversation_id)` rebuild it through the same `_restore_conversation` body, need `API(event_log=)`; a rebuilt pushed frame keeps the `max_steps` and `max_seconds` its push logged with a FRESH count, the API default fills a limit it never had). `restore_session` starts with `_suppress_start=True` (no START handlers, no greeting), seeds summary, history, provenance and working memory in one `seed_restored_conversation` call, then `set_conversation_state` (unknown state -> `FSMError`, half-restored conversation ended, and no ended-cache entry is left for the id: one it already had is kept). `restore_session` and the frames rebuilt by `fork` and `resume` seed only the public keys of the saved context (`runtime.stores.session.public_context`; `start_conversation` itself filters nothing), so a tampered session file cannot carry `_approval_granted` or `_run_output_keys` into a live context (plan 52ce5464 A1). A different `fsm_id` only warns. `FileSessionStore` ids match `[a-zA-Z0-9_\-]+`; values go through `context.filtering.redacting_json_default` (lossy: datetime-like -> `str()`, other non-JSON -> `"<redacted:TypeName>"`); the file holds the full context.
- `WorkingMemory` non-hidden buffers merge under `context.data` (data wins) for transition evaluation and Pass 2; hidden buffers reach nothing, except that the `core` buffer is always merged, whether or not it is named in `hidden_buffers` (`memory.py` `_get_all_data_locked`).
- Logging: `logger.disable("fsm_llm")` at import silences core and all subpackages until `setup_logging()` / `enable_debug_logging()`. `LIBRARY_LOGGER_NAMES` stays `("fsm_llm",)`; a subpackage must never call `logger.disable` itself (D-004). `setup_cli_logging` only from process entry points. `setup_logging()` and `enable_debug_logging()` call `replace_default_handler()` (a no-op when loguru's id 0 is gone or `LOGURU_AUTOINIT` is off); never remove id 0 without an equivalent sink for the host's own records. The JSON file sink writes `<` as the JSON escape `\u003c` and adds no `{exception}` tail, so loguru's markup parser cannot drop or reject a record.
- CLIs: reports and diagrams go to stdout, diagnostics to stderr. `fsm-llm`, `fsm-llm-validate`, `fsm-llm-visualize`, `fsm-llm-okf`: exit 0 ok, 1 failure, 130 Ctrl-C (`constants.CLI_EXIT_*`), 2 for an argparse usage error. `fsm-llm-validate` reports an unreferenced `handler_only_keys` entry as INFO. The runner prints the greeting, each `System:` reply, the exit hint and the final redacted `Data:` dump to stdout with `print()` and a failure to stderr (the file log keeps the `logger` records; library records never reach the terminal after `setup_file_logging`); it prints no `System:` line for a silent reply, and writes an unencodable character as `\uXXXX` (`cli_support.escape_unencodable_output`) instead of ending the session. Exit 2 is reserved: `fsm-llm-eval` returns it only when the score is below `--fail-under` (`eval/constants.EXIT_BELOW_THRESHOLD`). It uses a `_Parser` whose usage errors exit 1, not argparse's 2; keep it. `fsm-llm-eval` also exits 130 on Ctrl-C. A missing model or a missing `--env-file` is exit 1 with one stderr line in every CLI, `fsm-llm-eval` included.

## Failure modes

- Core exceptions: `FSMError` -> `ConversationBusyError`, `BuildError(FSMError, ValueError)` (a builder's `build()` refused; `.errors`, cause chained), `OKFError` (OKF missing root or refused write) and `SkillError` (Agent Skills caller misuse or a refused skill read; skill content never raises it), both defined in `core/definitions/errors.py` (so is `AgentError(FSMError)`, the root of the agents package, since step 85: the tool layer subclasses it for `ToolExecutionError` and `ToolNotFoundError`, which are defined in `fsm_llm.tools`; it is exported from `fsm_llm.agents` and `fsm_llm.core.definitions`, not from `fsm_llm`) and exported from `fsm_llm` and from `okf.__all__` / `agent_skills.__all__`, `FSMDefinitionNotFoundError(FSMError, ValueError)` (no FSM registry: a non-path id; message starts `Unknown FSM ID`), `StateNotFoundError`, `InvalidTransitionError`, `LLMResponseError`, `TransitionEvaluationError`, `ClassificationError` -> `ClassificationResponseError`, `RunBudgetExceededError(budget, limit, steps_done)`; `HandlerSystemError(FSMError)` -> `HandlerExecutionError(handler_name, original_error)`.
- `API` wraps unexpected exceptions as `FSMError`; `ValueError` for unknown conversation ids passes through. Invalid definitions raise `ValueError` from `process_fsm_definition`.
- `start_conversation` failure fires END_CONVERSATION handlers and frees resources; a failing END handler wins (chained).
- Classifier failure (`ClassificationError`) or low confidence degrades to "stay" or leaves the key unset (WARNING); other exceptions fail the turn.
- A reply cut off at `max_tokens` is not an exception: it sets `truncated` on the response and `CONTEXT_KEY_CUT_OFF` on the turn (only a bulk extraction whose cut reply is not valid JSON raises `LLMResponseError`, saying so; the pipeline's bulk call site swallows it into a WARNING and `extraction_failed`, so that turn does not fail, and a bulk cut is never recorded in the cut-off record). Carried into `AgentResult` only for the last turn of `_standard_run` patterns and ADaPT, and only when the answer text is what was cut (`stop_reason="truncated"`, D-027).
- `LLMInterface.complete` raises `LLMResponseError` for every failure (provider error chained, empty reply, unreadable shape, request that cannot be built); a provider malformed-tool-call error on a request with tools, and a call without id, name or object arguments, give `kind="malformed"` with no calls. The base method raises `NotImplementedError`, which a completion state reports as `LLMResponseError` naming the interface type.
- LLM reply parsing: `reasoning` is never shown to the user; an empty Pass-2 message becomes a generic apology, retried once (not on the stream path); `<think>` blocks and a leading code fence are stripped; uncoercible `confidence` becomes 0.5; a `bool` field reads the closed vocabulary of `core.coerce.parse_bool_word` (`true/yes/y/1`, `false/no/n/0`, case-folded, surrounding quotes and trailing `.!?,;:` ignored; shared by `pipeline._coerce_bool` and the `llm/parsing.py` unstructured rung) and any other string is an invalid extraction, never a confident `False`; an unparseable reply that opens with this field's own `{"field_name": ..., "value": ` envelope yields only its value on the `str`/`any` rung (a complete value whole, undefined escapes kept literally; a value cut off by `max_tokens` as its prefix at `TRUNCATED_SALVAGE_CONFIDENCE` 0.3 with a WARNING; D-050/D-056 of plan 06a5ec0a); `extract_json_from_text` returns a dict or None.
